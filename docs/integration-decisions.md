# 跨功能实施决策

由协调任务统一，供后续功能在读取最新 `feature-contracts.md` 后实施。此文件是接口方向，不代表功能已经实现。

## 用量事实、长期统计、费率及排行

- 长期统计不能只保存全局每日总量：保留可归属的来源/会话、日期、模型及输入/缓存输入/输出 Token 事实。已有明确会话身份与项目目录元数据时保留白名单字段，以便最后一项排行共用；不保存聊天正文。
- 同一事实版本生成今日、每日、模型、项目与会话汇总。活动与归档日志搬移/复制不应重复贡献，无法归属的历史明确单列，不编造会话数。
- 持久历史以 Token 事实为准；金额是派生结果。费率修改按当前有效价格重算保留范围内的全部历史，不改变 Token，不依赖源日志仍存在。
- 价格明确区分已知免费与未知价格；输入、缓存输入、输出单价都为零可以是合法免费价格。未知价格不套用其他模型。
- 定价以 USD 原始精度计算，币种与参考汇率只作用于显示和导出。每份发布结果包含一致的用量版本与价格版本；旧价结果不能覆盖新价结果。
- 默认保留90天，范围查询、图表和导出共用相同日期边界。已有日志可回填；已经删除且从未采集的日志无法恢复，界面必须如实说明覆盖范围。
- 长期统计负责单一持久事实存储，排行复用它，费率服务负责单一定价逻辑；不要引入三套互相漂移的统计缓存。

## 额度历史与预测

- 额度历史按账号摘要、稳定窗口身份、真实观测及周期边界隔离。不能从本地 Token 量换算订阅额度。
- 保存有效的同值在线观测或等价的明确时间区间，保证预测能区分空闲与断连；重复发布同一 ObservationId 不能新增样本。
- 重置、额度下降、缺测和账号切换明确分段；预测使用原始有效观测，不读取图表降采样结果。
- 周期容差必须相对固定锚点判断，不能逐次累积漂移。来源相对时间与精确绝对边界需要区别时，由采集契约兼容新增，不让各消费者猜测。

## 设置与验收

- 后续设置保留未修改的嵌套功能配置，尤其 Reminders 和任务栏显示配置；先持久化，后发布成功状态。
- 每项结束更新 `feature-contracts.md` 的实际字段和测试命令，由协调任务维护 `implementation-status.md`。
- 完整回归包括原生入口及 `node scripts/run-web-tests.cjs` 指定的所有功能浏览器脚本。浏览器服务仅使用合成数据，测试结束清理自身进程。
